- Traps worth remembering:
  - `Gpu::AllocationScope` is a rollback guard, not a lifetime owner: its destructor frees every GPU
    buffer allocated inside it. Holding one in `load()` produced `Invalid Resource` on first generate
    and a startup line `0.00 GB allocated`. Never use it across a constructor.
  - LFM3 `in_proj` emits `[T, 3H]` rows with (B, C, x) inside each row; `Buffer::view` offsets cannot
    split the planes at T > 1. `lfm3_bcx` reads them with a stride (decode T=1 can keep `lfm3_mul`).
  - `to_half` defaults to `hidden` as the row width; the FFN's `intermediate_size` rows need explicit `d`.
  - 8-bit `qmr8` kernels need 128 threads even for a single decode row; bf16 embedding is `embed_f16`.
- Verification entry points: `build/lfm3_kernel_check kernels|chain|sample|logits|tok`, and
  `lockf -k -t 0 /tmp/kapitsa-gpu.lock build/kapitsa serve --model <imported folder>`. Stop the serve
  before finishing: it holds the GPU lock and blocks other sessions' measurements.
